1. Summary
Today's payments-api deploy introduced a canary that began throwing elevated 5xx responses within 8 minutes of rollout. A rollback was initiated per runbook_rollback_payments_api.docx while investigation continued.
2. Impact
Affected services: payments-api (primary), checkout-service (downstream, elevated retry volume during the window). Approximately 6% of payment authorization requests were affected before rollback completed.
3. Root cause
Preliminary root cause: the canary build shipped with a lowered request-timeout default that was too aggressive for payments-api's p99 dependency latency to primary-db under normal load, causing a share of otherwise-healthy requests to time out and surface as 5xx. Confirmed by comparing the canary build's config diff against the previous stable release.
4. Root cause summary
Root cause category
Overly aggressive request-timeout default shipped in a canary build.
5. Roles & responsibilities
Incident commander: on-call SRE. Communications: owning team lead. Follow-up owner: Marisol Feng (FEN-1003) -- add a timeout-regression check to the canary gate.
